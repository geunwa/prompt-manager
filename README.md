# 파이썬 프롬프트 관리 프로그램

## 1. 프로젝트 개요
이 프로젝트는 자주 사용하는 AI 프롬프트를 콘솔 환경에서 저장, 조회, 검색, 관리할 수 있도록 만든 파이썬 프로그램입니다.  
사용자는 프롬프트를 추가, 전체 조회, 검색, 상세 보기, 즐겨찾기 설정/해제, 삭제할 수 있습니다.

추가 기능으로 다음 내용을 구현했습니다.
- JSON 파일 저장/불러오기
- 카테고리별 Markdown 내보내기
- 카테고리별 조회
- 즐겨찾기 전용 목록 조회

## 7. 데이터 구조 설계

### 7-1. 리스트를 사용한 이유
여러 개의 프롬프트를 순서대로 저장하고, 반복문으로 전체 출력하거나 검색하기 쉽기 때문에 리스트를 사용했습니다.

#### 장점
- 여러 프롬프트를 순서대로 저장하기 좋습니다.
- 전체 조회, 반복 처리에 적합합니다.
- 항목 추가가 직관적입니다.

#### 단점
- 특정 항목을 바로 찾는 속도는 딕셔너리 단독 구조보다 느릴 수 있습니다.
- 검색이나 삭제 시 반복문으로 순회해야 합니다.

---

### 7-2. 딕셔너리를 사용한 이유
프롬프트 1개는 제목, 내용, 카테고리, 즐겨찾기 여부처럼 여러 속성을 가지므로 딕셔너리로 묶어 저장했습니다.

예시:

```python
{
    "title": "자기소개서 첨삭",
    "content": "이 자기소개서를 첨삭해줘",
    "category": "글쓰기",
    "favorite": False
}
```

#### 장점
- 하나의 프롬프트 정보를 구조적으로 저장하기 좋습니다.
- `title`, `content`, `category`, `favorite`처럼 키 이름으로 의미가 분명합니다.
- JSON 변환이 쉽습니다.

#### 단점
- 키 이름을 일관되게 사용해야 합니다.
- 구조가 바뀌면 관련 함수도 함께 수정해야 합니다.

## 8. 함수 분리와 역할
프로그램은 기능별로 함수를 분리하여 작성했습니다.  
함수 분리를 통해 가독성과 유지보수성을 높이고, 기능 수정 시 영향 범위를 줄이도록 설계했습니다.

- `load_prompts()`  
  JSON 파일에서 프롬프트 데이터를 불러옵니다.

- `save_prompts(prompts)`  
  현재 프롬프트 목록을 JSON 파일에 저장합니다.

- `is_duplicate_title(prompts, title)`  
  새로 입력한 제목이 기존 프롬프트 제목과 중복되는지 확인합니다.

- `add_prompt(prompts)`  
  제목, 내용, 카테고리를 입력받아 새 프롬프트를 추가합니다.

- `list_prompts(prompts)`  
  저장된 전체 프롬프트 목록을 출력합니다.

- `search_prompts(prompts)`  
  제목 또는 내용 기준으로 프롬프트를 검색합니다.

- `view_prompt_detail(prompts)`  
  선택한 프롬프트의 상세 정보를 보여줍니다.

- `toggle_favorite(prompts)`  
  특정 프롬프트의 즐겨찾기 상태를 설정 또는 해제합니다.

- `list_favorites(prompts)`  
  즐겨찾기된 프롬프트만 따로 출력합니다.

- `list_by_category(prompts)`  
  사용자가 선택한 카테고리에 해당하는 프롬프트만 출력합니다.

- `delete_prompt(prompts)`  
  선택한 프롬프트를 삭제합니다.

- `export_markdown_by_category(prompts)`  
  프롬프트를 카테고리별로 묶어 Markdown 파일로 내보냅니다.

## 9. 중복 제목 처리 정책

### 정책
이 프로그램은 **동일한 제목의 프롬프트 추가를 허용하지 않는 방식**으로 설계했습니다.

- 새 프롬프트 추가 시 기존 제목과 같은 제목이 있으면 저장하지 않습니다.
- 사용자에게 중복 제목이라는 안내 메시지를 출력합니다.
- 제목이 같은 프롬프트가 여러 개 생겨 검색과 조회가 혼동되는 상황을 방지합니다.

### 이유
- 제목 기준 검색과 상세 조회 시 식별을 쉽게 하기 위함입니다.
- 목록에서 같은 제목이 반복되면 관리가 불편해질 수 있기 때문입니다.

### 구현 예시
```python
def is_duplicate_title(prompts, title):
    for prompt in prompts:
        if prompt["title"] == title:
            return True
    return False
```

## 10. 카테고리 처리와 수정 포인트

### 관련 기능
- `add_prompt(prompts)` : 카테고리 입력
- `list_by_category(prompts)` : 카테고리별 조회
- `export_markdown_by_category(prompts)` : 카테고리별 Markdown 저장

### 카테고리 종류를 바꾸려면
카테고리를 고정 목록으로 운영하는 경우 아래 위치를 함께 수정해야 합니다.

1. 카테고리 입력 안내 문구
2. 카테고리 선택 메뉴
3. 카테고리별 조회 함수
4. Markdown 내보내기 함수의 카테고리 묶음 처리 부분

즉, 카테고리 정책이 변경되면 **입력부 / 조회부 / 내보내기 함수**를 함께 점검해야 합니다.

## 12. 커밋 기준
커밋은 작업 목적이 섞이지 않도록 **한 커밋에 한 가지 목적만 담는 방식**으로 진행했습니다.

### 커밋 단위 예시
- 기능 추가: 프롬프트 검색 기능 구현
- 버그 수정: JSON 저장 오류 수정
- 문서 수정: README 업데이트
- 리팩토링: 함수 분리 및 코드 정리
- UI 수정: 메뉴 문구/번호 정리

이 기준을 사용한 이유는 변경 이력을 이해하기 쉽게 만들고, 문제가 발생했을 때 원인을 추적하기 쉽게 하기 위해서입니다.

## 13. 병합 충돌 해결 절차

### 13-1. 충돌 발생 원인
병합 충돌은 서로 다른 브랜치에서 같은 파일의 같은 부분을 수정했을 때 발생할 수 있습니다.

예시:
- `main.py`의 메뉴 출력 부분을 두 브랜치에서 각각 수정한 경우
- 같은 함수 내부 로직을 서로 다르게 변경한 경우

### 13-2. 해결 절차
1. `git merge 브랜치이름` 실행
2. 충돌 파일 확인
3. 충돌 표시(`<<<<<<<`, `=======`, `>>>>>>>`)를 보고 최종 코드로 직접 수정
4. 수정 후 저장
5. `git add .`
6. `git commit`

### 13-3. 검증 방법
- 프로그램을 다시 실행하여 메뉴와 기능이 정상 동작하는지 확인합니다.
- `git log --graph --oneline --all`로 병합 이력을 확인합니다.
- JSON 저장/불러오기, 즐겨찾기, 카테고리 조회 같은 핵심 기능을 재확인합니다.
